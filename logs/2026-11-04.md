## AI Agent — 1-3 LLM 기초 · 1-6 LangChain 답변 초안 체인
**배운 개념 (내 말로)**
- 체인은 `프롬프트 | 모델 | 출력 파서`를 파이프(`|`)로 이은 것이다. 입력 dict(`{"inquiry": ...}`)를 넣으면 끝에서 문자열이 나온다.
- `ChatPromptTemplate`은 system/human 메시지 틀에 `{inquiry}` 같은 빈칸을 둔다. 실행 전에 `reply_prompt.invoke(...)`로 실제 메시지가 어떻게 만들어지는지 먼저 확인할 수 있다.
- 회사 말투 규칙은 시스템 프롬프트에 번호 목록으로 정리해 둔다. 첫 인사, 공감 한 줄, 해결책 목록, 끝맺음이 들어간다. 특히 "모르는 날짜·금액·규정은 지어내지 말고 확인 후 안내"라는 규칙은 환각을 줄이는 장치다.
- 용도에 따라 temperature를 다르게 줬다. 요약은 `0`으로 늘 같은 결과가 나오게 하고, 답변 초안은 `0.3`으로 조금 자연스럽게 했다.

**내가 만든 것**
- `src/csagent/draft.py`: `make_summary_chain()`, `make_reply_chain()`
- `scripts/00_chain_steps.py`: 체인을 한 단계씩 나눠 확인하는 스크립트
- `scripts/02_draft_reply.py`: 문의 3건(E3 오류, 제주 배송, 초기 불량 교환)의 요약과 답변 초안 출력
- 커밋: `1일차: 요약.답변 초안 체인`

**결과**
- 문의마다 30자 이내 요약과 규칙에 맞는 답변 초안이 나왔다.
- 영어 문의(`My robot vacuum shows E4.`)를 하나 더 넣어 시험해 봤다. 아직 커밋하지 않았다.

## ROS — 영상 필터 · TF · 도메인 ID · 제어 (`r2r_ws`)
**1) 영상 필터 (실습 2-6, 2-7)**
- 만화 필터(`cartoon_styler`)
  - 양방향 필터(`bilateralFilter`)로 경계는 살리고 색만 단순하게 만든다.
  - `medianBlur` 후 Canny로 엣지를 뽑고, 반전(`255 - edges`)해서 검은 선을 만든다.
  - 두 결과를 합쳐 `/image_cartoon`으로 발행한다.
  - 엣지는 1채널이라 3채널로 바꿔야 합칠 수 있다.
- 광학 흐름(`optical_flow`)
  - 연속된 두 프레임의 픽셀 이동을 `calcOpticalFlowFarneback`으로 구한다.
  - 일정 간격(`step`)마다 화살표로 그려 `/image_optical_flow`로 발행한다.

**2) TF 좌표계 (3단원)**
- 브로드캐스터
  - `my_tf1`: `moving_frame`이 world를 반지름 2 m로 돈다. 위치만 바뀐다.
  - `my_tf2`: yaw까지 계산해서 x축이 늘 원점을 보게 한다. 오일러 각은 직접 만든 `tf_utils.quaternion_from_euler`로 쿼터니언으로 바꿨다.
- 계층 구조
  - `child_frame`은 부모(`moving_frame`) 기준 좌표만 계산한다.
  - 그래도 world에서 본 위치는 TF가 자동으로 이어 붙여 준다(world → moving_frame → child_frame).
  - `combined_frame`은 이 세 단계를 한 노드에서 보낸다.
- 리스너
  - `distance_world_child`: `lookup_transform('world', 'child_frame', Time())`으로 위치를 조회해 거리를 발행한다.
  - `frame_trail_marker`: 지나간 경로를 RViz 마커(LINE_STRIP + TEXT)로 보여 준다.
  - `frame_trail_path`: 같은 경로를 Nav2와 같은 `nav_msgs/Path` 형식으로 발행한다.
  - `max_points` 파라미터로 최근 N개 점만 남긴다.

**3) 도메인 ID 분리와 브리지**
- 한 프로그램 안에서 `rclpy.init(domain_id=1)`과 `rclpy.init(domain_id=2)`를 프로세스별로 따로 열었다. 토픽, 서비스, 액션 세 가지로 시험했다.
  - 토픽: 도메인 1에는 홀수, 도메인 2에는 짝수를 `/id_test`로 보냈다. 터미널마다 `export ROS_DOMAIN_ID=1/2`로 맞춘 쪽만 받았다.
  - 서비스: 도메인 1 거북이는 왼쪽, 도메인 2 거북이는 오른쪽으로 순간이동(`TeleportAbsolute`)시켰다.
  - 액션: 도메인 1은 +90°, 도메인 2는 −90°로 회전(`RotateAbsolute`)시켰다.
- `domain_bridge`에 `my_bridge.yaml`을 주면 도메인 1의 `/chatter`를 도메인 2로 넘겨 줄 수 있다. 분리는 유지하면서 필요한 토픽만 공유하는 방법이다.

**4) 거북이 회전 제어 (`controller_tutorials`)**
- `simple_rotate`: `/goal_theta`를 받아 오차가 `tolerance`보다 크면 일정 속도로 돌고, 작으면 멈춘다. 조건문만 쓰는 가장 단순한 제어다.
- 오차는 `atan2(sin, cos)`로 −π~π로 정규화한다. 그래야 늘 짧은 쪽으로 돈다.
- `/angle_error`를 `rqt_plot`으로 그려 오차가 줄어드는 모습을 봤다.

**실행한 것 (일부)**
```bash
ros2 launch my_opencv_tutorials cartoon_styler.launch.xml
ros2 launch my_opencv_tutorials optical_flow.launch.xml
ros2 run my_tf my_tf2
ros2 run my_tf frame_trail_path --ros-args -p max_points:=60
ros2 run rqt_tf_tree rqt_tf_tree --force-discover
python3 ~/r2r_ws/scripts/domain/domain_test_action.py
ros2 run domain_bridge domain_bridge my_bridge.yaml
ros2 run rqt_plot rqt_plot /angle_error/data
```

**결과**
- `my_opencv_tutorials`, `my_tf`, `controller_tutorials` 빌드 8번이 모두 성공했다(rc 0).
- RViz에서 프레임이 도는 모습과 경로를, rqt_tf_tree에서 world → moving_frame → child_frame 구조를 확인했다.

## 문제와 해결
| 문제 | 원인 | 해결 |
|---|---|---|
| `-p` 파라미터가 적용되지 않음 | `--ros-args -p m max_points:=60`처럼 이름 앞에 글자가 끼었다. | `-p 이름:=값` 형식을 지켜 `-p max_points:=60`으로 다시 실행했다. |
| `cd ~/r2r_Ws` 실패 | 리눅스는 대소문자를 구분한다. | `~/r2r_ws`로 다시 이동했다. |
| rqt_tf_tree에 새 프레임이 안 보임 | 처음 열 때 받은 TF만 보여 준다. | `--force-discover` 옵션으로 다시 열었다. |
| 다른 터미널의 토픽이 안 보임 | 터미널마다 `ROS_DOMAIN_ID`가 달랐다. | `export ROS_DOMAIN_ID=같은 값`으로 맞췄다. 일부러 나눈 경우에는 `domain_bridge`로 필요한 토픽만 넘겼다. |
| 각도 오차가 −π, +π 경계에서 튐 | 179°와 −179°는 실제로 2° 차이인데, 단순 뺄셈이면 358°가 된다. | `normalize_angle`(atan2)로 오차를 −π~π로 바꿨다. |
