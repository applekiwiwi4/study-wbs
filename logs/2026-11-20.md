## AI Agent — 3-4 GraphRAG 실습 ① (제품 지식그래프)
**배운 개념 (내 말로)**
- **LLM을 한 번도 부르지 않는 실습이다.** 그래프를 만들고 따라가는 일은 코드만으로 충분하다.
- **노드 이름 앞에 종류를 붙인다.** `product:P100`, `part:FM-20`, `error:P100-E3`, `dept:AS센터`처럼 붙이면 NetworkX에서도 레이블을 구분할 수 있다. 관계 이름은 엣지의 `rel` 속성에 넣었다.
- **3-3 이론의 질문 유형이 함수 하나씩이 됐다.**
  - `products_using_part`: 부품에서 제품으로 거꾸로(`predecessors`) 따라간다. 영향 범위 질의다.
  - `error_info`: 제품 → 오류 → 부품·부서로 여러 단계를 따라간다.
  - `errors_by_part`: 부품마다 연결된 오류 수를 센다. 집계다.
  - `fault_context`: 고객 문장에서 제품과 오류코드를 찾아 상담원에게 보여 줄 글로 정리한다. 에이전트가 이 함수만 부르면 된다.
- **그래프는 한 번만 만들어 재사용한다** (`graph()`가 `_G`에 저장).
- **정규식과 한글**: `\bE\d\b`로는 "E3가 떠요"에서 E3를 못 찾는다. 파이썬은 한글도 단어 글자로 봐서 `3`과 `가` 사이를 단어 경계로 보지 않는다. 그래서 `(?<![A-Za-z0-9])([Ee]\d)(?!\d)`로 바꿨다.
- **관계로 저장하면 데이터만 추가해도 답이 바뀐다.** 신제품을 넣으면 문서를 고치지 않아도 "FM-20 영향 제품"이 자동으로 늘어난다.

**내가 만든 것**
- `src/csagent/knowledge_graph.py`: `build_graph`, `find_product`, `products_using_part`, `error_info`, `errors_by_part`, `fault_context`
- `scripts/10_kg_explore.py`: 품질팀 질문 3가지 탐색

## ROS — 자율주행 과정 4일차 ① 이론·실습 준비 (Action·Launch·기록)
**배운 개념 (내 말로)**
- **모든 센서 메시지에는 `Header`가 있다.**
  - `stamp`: 측정 시각. LiDAR와 오도메트리처럼 다른 시각의 값을 맞춰 쓸 때 필요하다. SLAM과 AMCL은 이 시각으로 좌표 변환을 찾는다.
  - `frame_id`: 어느 좌표계 기준 값인지. 같은 "1m 앞"도 라이다 기준인지 로봇 중심 기준인지에 따라 다르다.
  - `use_sim_time:=true`면 모든 노드가 Gazebo의 `/clock`을 같이 쓴다. bag 기록에도 이 시각이 남는다.
- **주요 메시지**: `Twist`(linear.x, angular.z), `Odometry`(위치·속도), `PoseStamped`(Nav2 목표), `LaserScan`, `Imu`
  - 평면 로봇은 yaw만 쓰므로 쿼터니언을 `z = sin(yaw/2)`, `w = cos(yaw/2)`로 간단히 만든다.
- **Action 흐름**: 목표 전송 → 수락·거절 → 피드백 반복 → (취소) → 결과. Nav2의 `navigate_to_pose`, 도킹, 층간 이송이 모두 같은 구조이고, 오늘 만들 거리 주행은 그 축소판이다.
- **Executor와 콜백 그룹**
  - `rclpy.spin()`은 콜백을 한 번에 하나씩 실행한다. Action의 execute가 반복문으로 오래 돌면 그동안 `/odom` 콜백이 못 돌아서 위치가 갱신되지 않는다. 그러면 영원히 도착하지 못한다.
  - 그래서 `MultiThreadedExecutor`와 `ReentrantCallbackGroup`을 쓴다.
- **Launch와 YAML 파라미터**: 노드 여러 개를 한 번에 켜고, 설정은 코드와 분리한다. YAML은 `노드이름: ros__parameters:`(밑줄 2개) 형식이다. 우선순위는 코드 기본값 < YAML < 실행 인자다. 나중에 적용된 것이 이긴다.
- **사용자 정의 인터페이스는 `ament_cmake` 패키지에서만 만들 수 있다.** 그래서 파이썬 노드 패키지(`amr_basics`)와 따로 `amr_interfaces`를 둔다.
- **`ros2 bag`**: `record`는 토픽 메시지를 시각과 함께 저장하고, `play`는 그대로 다시 발행한다. 재생하는 동안 다른 노드는 실제 로봇이 있는 것처럼 데이터를 받는다.

**실행한 것** (실습 준비: 인터페이스 패키지)
```bash
cd ~/project_lift/ros2_ws/src
ros2 pkg create --build-type ament_cmake --license Apache-2.0 amr_interfaces
cd amr_interfaces && rm -rf include src && mkdir -p msg srv action
```
- 정의 파일 5개를 만들었다.
  - `action/DriveDistance.action`: 목표(distance, speed) / 결과(success, traveled, message) / 피드백(traveled, remaining). `---`로 셋을 나눈다.
  - `msg/RobotStatus.msg`: 로봇 1대의 상태, 배터리, 위치, 작업 ID (12·14일차)
  - `msg/Detection.msg`, `msg/DetectionArray.msg`: 비전 인식 결과 (7·14일차)
  - `srv/SubmitTask.srv`: 작업 등록 GOTO, DELIVER, CHARGE, PATROL, CANCEL (12·13일차)
- `CMakeLists.txt`에 `rosidl_generate_interfaces(...)`로 다섯 파일을 등록했다. `package.xml`에는 `rosidl_default_generators`와 `rosidl_interface_packages` 그룹을 넣었다.

## 문제와 해결
| 문제 | 원인 | 해결 |
|---|---|---|
| "E3가 떠요"에서 오류코드를 못 찾음 | `\b` 단어 경계는 숫자 뒤에 한글이 붙으면 경계로 보지 않는다. | 앞뒤가 영문·숫자가 아닌지만 보는 `(?<![A-Za-z0-9])([Ee]\d)(?!\d)`로 바꿨다. 소문자 e3도 찾는다. |
| 신제품을 추가해 본 뒤 다음 실습 결과가 달라질 수 있음 | 4-1에서 Neo4j 결과와 비교할 때 노드 수가 24개여야 한다. | 확인 후 `products.json`을 원래대로 되돌렸다. |
| Action 실행 중 위치가 갱신되지 않을 수 있음 | 기본 Executor는 콜백을 하나씩만 실행해서 execute 반복문이 `/odom` 콜백을 막는다. | `MultiThreadedExecutor`와 `ReentrantCallbackGroup`을 쓰기로 정리했다. ②에서 서버에 적용한다. |
| 메시지·액션 정의를 파이썬 패키지에 넣을 수 없음 | 인터페이스 생성은 `ament_cmake` 빌드 방식에서만 된다. | `amr_interfaces`를 따로 만들고 `amr_basics`가 의존하게 했다. |
