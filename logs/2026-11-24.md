## AI Agent — 4-3 n8n 실습 (문의 접수 자동화와 긴급 알림)
**배운 개념 (내 말로)**
- **n8n은 파이썬 함수를 직접 부를 수 없어서 주소(URL)를 만들어 준다.** FastAPI로 `api.py`를 만들었다.
  - `GET /health`: 서버가 살아 있는지 확인한다 (n8n 연결 테스트용).
  - `POST /classify`: 분류만 한다 (LLM 1회).
  - `POST /chat`: 에이전트 전체를 실행한다 (LLM 2회). n8n과 Dify가 쓴다.
  - `POST /review`: 승인 대기 건을 승인하거나 수정한다 (상담원 화면용).
  - `GET /orders/{번호}`: 주문 조회 (5-1 Dify에서 쓴다).
  - 요청 모양은 pydantic `Inquiry(text, thread_id)`로 정했다. `/docs`에 테스트 화면이 자동으로 생긴다.
- **워크플로 5개 노드**
  1. Webhook (문의 접수): POST, 경로 `cs-inquiry`
  2. HTTP Request (CS 에이전트 호출): `http://host.docker.internal:8000/chat`, Timeout 120초, 실패하면 5초 뒤 한 번 더
  3. Edit Fields (결과 정리): 문의ID, 채널, 문의, 분류, 긴급도, 상담원확인, 답변초안 7칸만 남긴다.
  4. IF (긴급 문의인가?): 긴급도가 "높음" **또는** 상담원 확인이 true
  5. HTTP Request (Discord): 웹후크로 알림. Discord는 2,000자 제한이라 `.slice(0, 1900)`으로 자른다.
- **`thread_id`에 문의 ID를 넣었다.** 같은 고객이 같은 문의 건으로 다시 글을 쓰면 3일차 체크포인터 덕분에 에이전트가 앞 대화를 기억한다.
- **웹후크 URL은 비밀번호처럼 다룬다.** 주소를 아는 사람은 누구나 채널에 글을 쓸 수 있다. 워크플로 JSON을 저장할 때 내 웹후크 주소가 들어가지 않았는지 확인한다.
- **Test URL과 Production URL이 다르다.** 테스트할 때는 `webhook-test/cs-inquiry`로 보내고 "Listen for test event" 상태에서 받는다.
- **"판단은 파이썬, 연결은 n8n"이 실제로 나뉘었다.** n8n 쪽에는 분류 규칙이 하나도 없다. IF 노드는 에이전트가 정한 긴급도와 상담원 확인 칸만 본다.

**실행한 것**
```bash
cd src && uvicorn csagent.api:app --port 8000          # 터미널 1: API 서버 (계속 켜 둠)
docker volume create n8n_data
docker run -it --rm --name n8n -p 5678:5678 -v n8n_data:/home/node/.n8n docker.n8n.io/n8nio/n8n
python scripts/13_send_inquiries.py http://localhost:5678/webhook-test/cs-inquiry 1   # 한 건 테스트
```

**내가 만든 것**
- `src/csagent/api.py`: FastAPI 주소 5개
- `n8n/cs_inquiry_triage.json`: 가져온 워크플로에 내 Discord 웹후크를 연결 (웹후크 주소는 저장소에 넣지 않음)
- `scripts/13_send_inquiries.py`: `inquiries.csv` 문의를 게시판처럼 웹후크로 보내는 스크립트. 무료 한도 때문에 5초 간격으로 보낸다.

**결과**
- `/docs`에서 `GET /health`가 `{"status": "ok"}`를 돌려줬다.
- `POST /chat`에 "제습기에서 타는 냄새가 나고 연기가 조금 났어요."를 보내자 응답에 `ticket.urgency`, `ticket.needs_human`, `answer`가 들어 있었다. n8n이 받을 데이터가 바로 이것이다.
- n8n 실행 기록에서 노드마다 입력과 출력을 따라가며 확인했다. 긴급 문의는 IF의 true 쪽으로 가서 Discord 채널에 알림이 왔다. 일반 문의는 false 쪽에서 끝났다.

## ROS — 자율주행 과정 5일차 ② 실습 (센서 데이터 처리와 시각화)
**배운 개념 (내 말로)**
- **`image_utils.py`**: `cv_bridge` 없이 Image ↔ numpy를 직접 바꾼다. `msg.step`(한 줄의 실제 바이트 수)으로 줄 길이를 맞춘 뒤 모양을 만든다. 깊이는 가까울수록 빨간 컬러맵으로 바꿔 본다.
- **`scan_analyzer.py`**: `/scan`을 전·좌·우·후 구역으로 나눠 최소 거리를 낸다.
  - 각도는 `angle_min + arange(len) × angle_increment`로 한 번에 계산하고, 장착 각도(90도)를 더한다.
  - `isfinite`, `range_min`, `range_max`로 유효값만 남긴다.
  - 전방 구역은 0도를 걸쳐 있어서(-30~30도) "또는"으로 고른다.
  - 결과는 `/amr/obstacle_state`에 JSON 문자열로, 가장 가까운 점은 `/amr/nearest_obstacle` Marker로 보낸다.
- **`imu_monitor.py`**: 쿼터니언을 roll·pitch·yaw로 바꾸고, 기울기와 수평 충격(`hypot(ax, ay)`, 중력이 있는 z는 제외)이 기준을 넘으면 `/amr/alerts`로 경보를 보낸다. 각속도를 적분한 yaw도 따로 계산해서 드리프트를 관찰한다.
- **`camera_viewer.py`**: 컬러와 깊이 영상을 OpenCV 창에 나란히 보여 주고, 화면 중앙의 깊이를 표시한다. `s`로 스냅샷을 저장한다(7일차 YOLO 시험용).
- **리매핑 `-r cmd_vel:=cmd_vel_raw`**: 키보드 조종 노드의 코드를 고치지 않고 보내는 토픽만 바꿔서 안전 노드를 거치게 했다. 제조사 노드를 우리 토픽 이름에 맞출 때 쓰는 방법이다.
- **교차 확인**: `safety_stop`과 `scan_analyzer`는 코드가 다르지만 같은 LiDAR, 같은 보정, 같은 ±30도 전방 구역을 쓴다. 두 값이 같아야 정상이다.

**실행한 것**
```bash
lift_build && ros2 pkg executables amr_basics | wc -l        # 8
ros2 run amr_basics scan_analyzer --ros-args -p use_sim_time:=true
ros2 run amr_basics scan_analyzer --ros-args -p use_sim_time:=true -p use_tf:=false -p scan_yaw_offset_deg:=0.0   # 보정 끄기 실험
ros2 run amr_basics imu_monitor --ros-args -p use_sim_time:=true
ros2 run amr_basics camera_viewer --ros-args -p use_sim_time:=true -p show_depth:=true
ros2 launch amr_basics sensors.launch.py                       # scan_analyzer + imu_monitor + safety_stop
ros2 run teleop_twist_keyboard teleop_twist_keyboard --ros-args -r cmd_vel:=cmd_vel_raw
rviz2 -d ~/project_lift/params/sensors.rviz --ros-args -p use_sim_time:=true
```

**결과**
- 실행 이름이 8개가 됐다 (3·4일차 5개 + 오늘 3개).
- 제자리에서 돌리면 가까운 벽이 있는 방향의 값이 작아졌다. RViz에는 가장 가까운 점이 빨간 공으로 표시됐다.
- 장착 각도 보정을 끄자 정면에 있는 벽이 `left` 값으로 나왔다. 90도 어긋난 것이다. 원래대로 되돌렸다.
- 여러 바퀴 회전한 뒤 IMU의 자세 yaw와 적분 yaw 사이에 차이가 생겼다. 회전을 많이 할수록 차이가 커졌다. 자이로 적분 드리프트다.
- 카메라 창에서 컬러와 깊이 컬러맵을 보고, 다른 장면으로 스냅샷 3장을 `media/snapshots`에 저장했다.
- 벽으로 천천히 다가가며 `/safety_state`의 거리와 `scan_analyzer`의 `front` 값을 비교했다. 두 값이 같게 나왔다.
- LaserScan, Marker, 카메라 Image, TF, RobotModel을 넣은 RViz 화면을 `params/sensors.rviz`로 저장했다.
- `5일차: 센서 처리 노드, sensors.launch, sensors.rviz`로 커밋했다.

## 문제와 해결
| 문제 | 원인 | 해결 |
|---|---|---|
| n8n에서 `localhost:8000`으로 API를 부르면 연결이 안 됨 | Docker 컨테이너 안의 localhost는 컨테이너 자신이다. | `http://host.docker.internal:8000/chat`으로 불렀다. |
| 에이전트 응답이 늦으면 HTTP Request가 시간 초과로 실패할 수 있음 | `/chat`은 LLM을 2번 부르고 문서 검색도 해서 기본 대기 시간보다 오래 걸릴 수 있다. | Timeout을 120초로 늘리고, 실패하면 5초 뒤 한 번 더 시도하게 했다. |
| 긴 답변이 Discord에 안 올라갈 수 있음 | Discord 메시지는 2,000자 제한이 있다. | 보내기 전에 `.slice(0, 1900)`으로 잘랐다. |
| 정면의 벽이 왼쪽 거리로 나옴 (실험) | 장착 각도 보정을 끄면 라이다 기준 0도가 로봇 왼쪽이다. | TF로 보정하는 원래 설정으로 되돌렸다. 센서를 바꾸면 이 값부터 검증해야 한다는 것을 배웠다. |
| 안전 노드와 함께 키보드로 조종하면 안전 노드를 건너뛸 수 있음 | teleop은 기본으로 `/cmd_vel`에 바로 보낸다. | `-r cmd_vel:=cmd_vel_raw`로 리매핑해서 안전 노드를 거치게 했다. |

## English (30 min) — Sunshine

- 새 단어

  - get some fresh air (바람 쐬다), sunglasses (선글라스)
  - make the most of ~ (~을 최대한 즐기다)
- 대화: *What a lovely day! — Let's make the most of it and eat outside. — Don't forget to put on sunscreen.*
- 말하기·쓰기 (맑은 날 하는 일 3문장)
  1. On a sunny day, I go out to get some fresh air.
  2. I always put on sunscreen and my sunglasses.
  3. I try to make the most of the sunshine by walking in the park.
