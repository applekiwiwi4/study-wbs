## AI Agent — 4-1 GraphRAG 실습 ② (Neo4j와 에이전트 연결)
**배운 개념 (내 말로)**
- **Neo4j AuraDB Free**: 클라우드 그래프 DB. 접속 정보(URI, 사용자, 비밀번호)는 `.env`에만 두고 커밋하지 않는다. 3일 동안 안 쓰면 일시정지되므로 다음에 콘솔에서 Resume한다.
- **적재는 `MERGE`로 한다** (`kg_neo4j.py`).
  - `LOAD_PART`, `LOAD_PRODUCT`, `LOAD_ERROR` 세 Cypher에 `$id`처럼 파이썬 값을 넣는다.
  - `UNWIND $parts`로 제품의 부품 목록을 한 줄씩 펼쳐 `HAS_PART`를 만든다.
  - 실습용이라 적재 전에 `MATCH (n) DETACH DELETE n`으로 모두 지운다.
- **템플릿 질의 `FAULT_CYPHER`**: 제품과 오류코드만 바꿔 넣는다. `OPTIONAL MATCH`로 같은 부품을 쓰는 다른 제품을 붙이고, 없으면 빈 목록이 된다.
- **같은 모양의 글을 돌려주면 에이전트 코드는 그대로다.** `fault_context_neo4j`가 NetworkX 버전과 같은 형식의 글을 만든다. `.env`의 `GRAPH_BACKEND`만 바꾸면 백엔드가 바뀐다.
- **Text2Cypher (`GraphCypherQAChain`)**: LLM에게 그래프 스키마를 주고 자연어 질문을 Cypher로 바꿔 실행하게 한다.
  - `validate_cypher=True`로 관계 방향을 점검한다.
  - `allow_dangerous_requests=True`는 LLM이 만든 쿼리를 실행해도 된다는 동의다. 실습 DB에서만 쓴다.
- **에이전트 연결은 노드 안에서만 바꿨다.** `retrieve` 노드에서 고장AS 문의일 때 `context`에 `fault_context(...)`를 더했다. 그래프 구조(노드·엣지)는 바꾸지 않았다.

**내가 만든 것**
- `src/csagent/kg_neo4j.py`: 적재 Cypher, `load_to_neo4j`, `FAULT_CYPHER`, `fault_context_neo4j`, `make_text2cypher`
- `scripts/11_build_neo4j.py` (적재와 확인), `scripts/12_text2cypher.py` (자연어 질문)
- `src/csagent/agent.py` 수정: `retrieve`에 고장 문의 그래프 정보 3줄 추가

**결과**
- 레이블별 개수: Product 3, Part 10, Error 9, Dept 2 (NetworkX와 같다)
- Cypher 연습 문제 (데이터로 확인한 답)

| 번호 | 질문 (요청 부서) | 답 |
|---|---|---|
| 1 | 보증 2년 이상 부품과 사용 제품 (AS센터) | FM-20 팬 모터 3년(AirPure 300, DryMax 16L), CP-16 컴프레서 3년(DryMax 16L), BM-07 브러시 모터 2년(RoboClean X) |
| 2 | '대성모터' 부품에 문제가 생기면 영향받는 제품 (구매팀) | FM-20과 BM-07 → 제품 3개 모두 |
| 3 | 고객지원팀이 처리하는 오류코드 (고객지원팀) | AirPure 300 E1 필터 교체 알림 / RoboClean X E1 바퀴 걸림, E5 브러시 모터 과부하 / DryMax 16L E1 물통 가득 참 |
| 4 | 두 제품 이상이 함께 쓰는 부품 (품질관리팀) | FM-20, PB-A (둘 다 AirPure 300과 DryMax 16L) |

  ```cypher
  // 2번: 공급사 하나가 문제면 전 제품이 영향을 받는다
  MATCH (pr:Product)-[:HAS_PART]->(p:Part {supplier: "대성모터"})
  RETURN p.id, collect(pr.name) AS products
  ```
- 엑셀로 풀면 제품표, 부품표, 오류표를 몇 번씩 찾아 맞춰야 하는 질문이다. 그래프에서는 한 줄짜리 MATCH였다.
- Text2Cypher: 세 질문 모두 Cypher를 만들어 답했다. 다만 질문 표현에 따라 쿼리 모양이 달라졌다. "모든 데이터를 지워 줘" 같은 입력이 들어오면 삭제 쿼리가 실행될 수 있다는 점이 핵심 위험이었다.
- **에이전트 연결 전후 비교** ("공기청정기 E3, 바람이 안 나와요. 산 지 2년 됐어요.")

| 비교 항목 | 연결 전 | 연결 후 |
|---|---|---|
| 조치 방법 | 매뉴얼대로 재시작 안내 | 같음 |
| 2년 사용 → 무상 수리 가능? | 모름 | 팬 모터 FM-20은 보증 3년이라 무상 수리 가능 |
| 담당 부서 | 일반 AS 안내 | AS센터 |

- 매뉴얼에는 "팬 모터 이상"만, 정책에는 보증 기간만, 부품 데이터에는 E3 원인 부품만 있었다. 흩어진 정보를 그래프가 연결해 줬다.
- `GRAPH_BACKEND`를 `networkx`와 `neo4j`로 바꿔 돌려도 같은 정보가 나왔다.

## ROS — 자율주행 과정 4일차 ② 실습 (Action과 한 줄 기동, 그리고 기록, M1)
**배운 개념 (내 말로)**
- **Action 서버 `drive_distance_server.py`** (`/amr/drive_distance`)
  - `/odom`으로 이동 거리를 재고, `/cmd_vel_raw`로 명령한다. 3일차 원칙대로 안전 노드를 거친다.
  - `on_goal`: 5m가 넘는 요청은 거절한다(입력 검증).
  - `on_cancel`: 취소를 받아들이고, 반복문 안에서 `is_cancel_requested`를 계속 확인한다.
  - `publish_feedback`으로 이동 거리와 남은 거리를 알리고, 끝나면 `succeed()` 또는 `canceled()`
- **Action 클라이언트**: `wait_for_server(5초)` → `send_goal_async(피드백 콜백)` → `get_result_async()`. 명령줄 인자로 거리와 속도를 받는다.
- **`basics.launch.py` + `params/basics.yaml`**: 안전 노드, 상태 서버, 액션 서버를 한 줄로 켠다. 적용 순서는 YAML → `use_sim_time` → 실행 인자다.
- **Service 대신 Action인 이유**: 수십 초 걸리는 주행은 "진행 중인지, 얼마나 남았는지, 멈출 수 있는지"를 알아야 한다.
- **상위 작업은 "진행 중"인데 실제로는 안전 정지인 상태**가 생긴다. 그래서 12일차 작업 실행기에는 "진척이 없으면 실패"로 판단하는 감시가 들어간다.

**실행한 것**
```bash
lift_build && ros2 pkg executables amr_basics                  # 실행 이름 5개
ros2 launch amr_basics basics.launch.py                        # T2: 노드 3개
ros2 action info /amr/drive_distance
ros2 run amr_basics drive_distance_client 1.0 0.2               # 1m 전진
ros2 run amr_basics drive_distance_client -1.0 0.2              # 1m 후진
ros2 run amr_basics drive_distance_client 6.0 0.2               # 거절 확인
ros2 action send_goal --feedback /amr/drive_distance amr_interfaces/action/DriveDistance "{distance: 3.0, speed: 0.15}"   # 도중 취소
ros2 launch amr_basics basics.launch.py slow_dist:=1.0 stop_dist:=0.6
ros2 bag record -o bag_d04 /odom /scan /imu /tf /tf_static /cmd_vel /cmd_vel_raw /safety_state
ros2 bag play bag_d04 --loop
rqt
```

**결과**
- 1m 전진과 후진이 피드백과 함께 끝나고 `success=True`가 왔다.
- 6m 요청은 서버가 거절했다. 3m 목표는 도중에 Ctrl+C로 취소하자 로봇이 멈췄다.
- 상자 앞에 목표를 보내자 로봇이 감속하다 멈추고, 피드백의 `remaining`이 더 줄지 않았다. 액션 서버는 계속 전진을 요청하지만 안전 노드가 막는 상태다.
- 실행 인자로 `stop_dist:=0.6`을 주자 YAML 값 대신 0.6이 적용됐다. `max_speed`처럼 인자로 안 준 값은 YAML 값이 그대로 남았다.
- 1m 왕복을 bag으로 기록했다. 시뮬레이터를 끈 뒤 재생해도 `/odom` 위치와 `/safety_state`가 다시 나왔다.
- rqt Plot에서 `/cmd_vel_raw`(원하는 속도)와 `/cmd_vel`(실제 나간 속도)이 감속 구간에서 갈라지는 것을 봤다.
- `4일차: amr_interfaces, drive_distance action, basics.launch (M1)`로 커밋하고 `M1` 태그를 달았다. bag 폴더는 용량이 커서 .gitignore로 뺐다.

## 문제와 해결
| 문제 | 원인 | 해결 |
|---|---|---|
| LLM이 만든 Cypher를 그대로 실행하면 데이터가 지워질 수 있음 | Text2Cypher는 입력에 따라 삭제 쿼리도 만들 수 있다. | 상담원 화면처럼 자주 쓰는 질문은 템플릿 질의(`FAULT_CYPHER`)로 하고, Text2Cypher는 읽기 전용 계정으로 분석가만 쓰는 것으로 정리했다. |
| 2년 쓴 제품의 무상 수리 여부를 답하지 못함 | 보증 기간(정책), 원인 부품(부품 데이터), 증상(매뉴얼)이 서로 다른 곳에 있었다. | `retrieve` 노드에서 고장 문의면 그래프 정보를 근거에 더했다. 그래프 구조는 그대로 두고 노드 안만 바꿨다. |
| 상자 앞에서 Action이 끝나지도 실패하지도 않음 | 안전 노드가 전진을 막지만 액션 서버는 목표에 도달할 때까지 계속 기다린다. | 이번에는 Ctrl+C로 취소했다. 진척이 없으면 실패로 판단하는 감시가 필요하다는 것을 메모해 두었다(12일차). |
| bag 용량이 커질 수 있음 | `-a`로 전부 기록하면 카메라 영상까지 들어간다. | 필요한 토픽 8개만 골라 기록하고, bag 폴더는 git에 넣지 않았다. |
