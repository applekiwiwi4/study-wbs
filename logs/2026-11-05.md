## ROS — 거북이 PID 제어와 상태 기계 (`controller_tutorials`)
**배운 개념 (내 말로)**
- **PID** 출력은 `u = P·오차 + I·오차의 누적 + D·오차의 변화율`이다.
  - P: 지금 오차만큼 민다. 너무 크면 목표를 지나쳐 흔들린다.
  - I: 오차가 조금씩 남을 때 그 누적으로 마저 밀어 준다.
  - D: 오차가 빨리 줄어들면 미리 브레이크를 건다. 흔들림을 줄인다.
- PID를 실제로 쓰려면 안전장치가 필요하다. 직접 만든 `pid.py`에 넣은 것들이다.
  - **출력 제한(saturation)**: 계산된 값이 커도 최대 각속도·선속도를 넘지 않게 자른다.
  - **적분 제한(i_limit)**: 출력이 막혀 있는 동안 적분이 계속 쌓이면, 나중에 크게 튀어 나간다(적분 와인드업). 그래서 누적값에 상한을 둔다.
  - **dt = 0 처리**: 첫 호출 때 0으로 나누지 않게 미분을 0으로 둔다.
  - **reset()**: 목표가 바뀌면 이전 오차와 적분을 지운다.
- PID 클래스는 ROS와 무관한 순수 파이썬으로 따로 뒀다. 그래서 회전 제어에도 위치 제어에도 그대로 다시 쓸 수 있다.
- **위치 제어**(`pose_dual_controller`)는 PID를 두 개 쓴다.
  - 선속도 PID: 목표까지 거리 오차를 줄인다.
  - 각속도 PID: 목표 방향과 현재 방향의 각도 오차를 줄인다.
- **상태 기계**(`move_turtle_state_machine`)는 동작을 단계로 나눈다.
  - `Idle → 목표 방향으로 회전 → 직진 → 최종 자세로 회전 → 도착`
  - 각 상태는 `enter()`, `update()`를 갖고, `CONTINUE`/`COMPLETE`로 다음 상태로 넘어갈지 알린다.
  - "제자리 회전 후 직진"은 동시에 돌며 가는 방식보다 사람이 로봇의 다음 움직임을 예측하기 쉽다. 그래서 현장에서는 더 안전하다.
- **모니터**(`turtle_monitor`)는 matplotlib으로 거북이 위치, 목표, 현재 상태를 그린다.
  - 마우스로 누른 곳이 목표 위치, 끌어서 놓은 방향이 최종 자세가 되어 `/goal_pose`로 발행된다.

**실행한 것**
```bash
colcon build --symlink-install --packages-select controller_tutorials
ros2 run controller_tutorials pid_rotate
ros2 topic pub --once /goal_theta std_msgs/msg/Float64 "{data: 2.0}"
ros2 run rqt_plot rqt_plot /angle_error/data /control_output/data

ros2 run controller_tutorials pose_dual_controller
ros2 topic pub --once /goal_pose turtlesim/msg/Pose "{x: 9.0, y: 9.0, theta: 0.0}"
ros2 run rqt_plot rqt_plot /distance_error/data /angle_error/data

ros2 run controller_tutorials move_turtle_state_machine
ros2 topic echo /controller_state
ros2 run controller_tutorials turtle_monitor
ros2 run rqt_reconfigure rqt_reconfigure      # 실행 중 P, I, D 값 조절
```

**결과**
- `controller_tutorials` 빌드 4번이 모두 성공했다(rc 0).
- rqt_plot에서 각도 오차는 0으로 수렴했고, 제어 출력은 상한에서 잘린 뒤 줄어드는 모양을 확인했다.
- 거북이를 (9,9), (1,1), (1,9), (2,8, θ=3.14) 같은 목표로 보내 봤다. `/controller_state`로 상태가 바뀌는 순서도 확인했다.

## 문제와 해결
| 문제 | 원인 | 해결 |
|---|---|---|
| 목표 위치 발행 실패 | YAML에서 `y:9.0`처럼 콜론 뒤에 공백이 없으면 키-값으로 읽히지 않는다. 메시지 타입과 `"{...}"` 사이를 붙여 쓴 경우도 있었다. | `"{x: 9.0, y: 9.0, theta: 0.0}"`처럼 콜론 뒤와 타입 뒤에 공백을 넣었다. |
| colcon 빌드 오류 | `--packages-selecect` 오타 | `--packages-select`로 고쳐 다시 빌드했다. |
| 붙여넣은 명령 앞에 `[200~`이 붙어 실행 안 됨 | 터미널이 붙여넣기 모드 표시 문자를 같이 넣었다. | 명령을 다시 입력했다. |
| 게인을 바꿔도 반응을 감으로만 판단함 | 숫자만 보고는 흔들림, 수렴 속도가 안 보였다. | rqt_reconfigure로 P/I/D를 바꾸면서 rqt_plot으로 오차 그래프를 동시에 봤다. |
