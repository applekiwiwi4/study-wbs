## AI Agent — 5-1 Dify 실습 (고객용 챗봇 만들고 공개하기)
**배운 개념 (내 말로)**
- **모델은 내 키로 연결한다.** 모델 공급자에 Gemini 키를 등록하고, 추론 모델과 임베딩 모델을 모두 Gemini로 정했다. 그러면 Sandbox 크레딧 200개가 아니라 내 무료 한도를 쓴다.
- **지식베이스 설정은 2일차 RAG와 같은 전략으로 맞췄다.**
  - 구분자 `##`(소제목 단위), 최대 길이 400, 겹침 50
  - 인덱스는 고품질, 검색은 하이브리드, Top K 4
- **검색 방식 비교**: "제습기 E6"처럼 기호가 들어간 질문은 벡터 검색만으로는 약하고 전문(키워드) 검색이 강하다. 하이브리드는 둘을 합친다. 2일차 이론에서 배운 내용을 화면에서 설정만 바꿔 확인했다.
- **5분 챗봇의 한계**: 지식베이스만 붙인 챗봇은 정책 질문에는 답하지만 주문번호 질문에는 답하지 못한다. 주문 데이터를 모르기 때문이다. 그래서 Chatflow로 분기를 만들었다.
- **Chatflow 구성**
  1. 질문 분류기(`sys.query`): 1 주문 조회 / 2 문의 / 3 기타. 클래스 설명을 글로 분명하게 쓰는 것이 정확도를 좌우한다. 2일차 `Ticket.category` 설명 쓰기와 같다.
  2. 주문 조회: 매개변수 추출(`order_id`, HB-YYYYMMDD-NNN 형식) → HTTP 요청(`GET /orders/{order_id}`) → LLM이 조회 결과만 보고 3줄 안내 → 답변
  3. 문의: 지식 검색 → LLM(문서 근거로만 답, 메모리 켬) → 답변
  4. 기타: LLM이 챗봇이 도와줄 수 있는 세 가지를 안내 → 답변
- **터널은 공개 주소다.** `cloudflared tunnel --url http://localhost:8000`으로 만든 주소는 누구나 접근할 수 있고 실행할 때마다 바뀐다. 실습이 끝나면 바로 끈다.
- **DSL을 저장할 때 터널 주소를 지운다.** `https://YOUR-API-URL`로 바꿔서 저장소에 주소가 남지 않게 한다.
- **포트폴리오 데모 링크**: 터널이 꺼지면 주문 조회가 안 되므로, 항상 동작하는 공개 링크는 지식베이스만 쓰는 FAQ 봇으로 하고 Chatflow는 화면 녹화로 보여 준다.

**실행한 것**
```bash
cd src && uvicorn csagent.api:app --port 8000        # 터미널 1: 4일차 API 서버
winget install --id Cloudflare.cloudflared
cloudflared tunnel --url http://localhost:8000       # 터미널 2: 임시 공개 주소
# 브라우저에서 https://<터널주소>/orders/HB-20261019-002 로 주문 정보 확인
```

**내가 만든 것**
- Dify 지식베이스: `data/docs/`의 md 문서 7개
- "한빛가전 FAQ 봇" (챗봇, 지식베이스만 사용, 인용 표시)
- "한빛가전 고객 챗봇" (Chatflow, 주문 조회 API 연결)
- `dify/hanbit_customer_chatflow.yml`: DSL 내보내기 (터널 주소는 `https://YOUR-API-URL`로 바꿈)
- `docs/dify_chatflow.png`: Chatflow 캔버스 캡처
- `5일차: Dify 고객 챗봇`으로 커밋

**결과**
- 검색 테스트 화면에 2일차 평가 질문 5개를 넣어 1위 조각의 문서를 정답 문서와 비교했다.
- FAQ 봇은 정책 질문에 답하며 인용 문서를 보여 줬고, 주문번호 질문에는 답하지 못했다.
- Chatflow 미리보기에서 주문번호 질문은 주문 조회로, 오류코드·반품 질문은 문의로, 인사는 기타로 갔다. 추적(Tracing) 탭에서 노드별 입력·출력과 시간을 확인했다. 3일차 `stream` 출력을 화면으로 보는 것과 비슷했다.
- 게시한 뒤 웹앱 주소를 휴대폰으로 열어 대화했다.
- 실습이 끝난 뒤 터널을 `Ctrl+C`로 껐다.

## ROS — 자율주행 과정 6일차 ② 실습 (SLAM 운영 맵과 검수, M2)
**배운 개념 (내 말로)**
- **월드는 설계표(CSV) → 생성기 → SDF 순서로 만든다.** `walls.csv`의 스테이션 표식 좌표(S1~S4, CHG, ELV_F1·F2, D1·D2)가 앞으로 스테이션 파일과 순간이동 좌표에 그대로 쓰인다. 바닥 표식은 충돌체가 없어서 지도에는 안 나온다.
- **`project_world.launch.py`**: Gazebo 서버와 화면을 따로 켜고(`headless:=True`면 화면 생략), `robot_state_publisher`로 로봇 형상을 TF로 방송하고, Nav2의 `spawn_tb4.launch.py`로 스폰과 토픽 브리지를 한다. 기본 스폰 자리는 S1(-5.0, -3.5, yaw 0)이다.
- **`where_am_i.py`**: `Buffer`와 `TransformListener`로 TF를 받아 `lookup_transform(fixed, 'base_link', Time())`으로 로봇 위치를 구한다. 로봇 앞 1m 지점은 위치 + (cos yaw, sin yaw)다. 7일차에 카메라로 찾은 물체를 지도 좌표로 바꾸는 계산의 기초다.
  - odom 기준으로는 스폰 자리가 (0, 0)이다. 월드 좌표로는 (-5.0, -3.5)다.
  - 지금 TF 트리에는 `map`이 없다. SLAM이나 AMCL이 아직 `map→odom`을 발행하지 않기 때문이다.
- **SLAM 지도 그리기 규칙**: 0.1~0.15m/s로 천천히, 회전은 더 천천히, 외곽 벽을 먼저 한 바퀴 돌고 안쪽 통로로, 좁은 통로는 가운데로, 마지막에 출발점으로 돌아와 루프 클로저를 만든다. RViz Fixed Frame을 `map`으로 바꾸는 것을 잊지 않는다.
- **저장은 두 가지**: `map_saver_cli`로 `.pgm`+`.yaml`, `serialize_map` 서비스로 포즈 그래프. 저장한 yaml의 origin은 스폰 자리 기준 값이다.
- **원점 정렬 `align_map.py`**: yaml의 origin에 스폰 좌표(`--dx -5.0 --dy -3.5`)를 더한다. 이후 지도 좌표 = 월드 좌표가 되어 설계표의 스테이션 좌표를 그대로 쓸 수 있다.
- **기준 맵(정답지)**: `make_map.py`가 설계표에서 바로 지도를 만든다. 벽을 그리고 S1에서 빈 공간을 번지듯 채워서(flood fill) SLAM 결과와 비슷한 모양이 된다. 검수 정답지이고, 내 지도가 불합격일 때 대신 쓰는 수단이다.
- **GIMP 후처리**: 점 노이즈와 작업자 자국은 흰색(255), 끊긴 벽은 검정(0), 지도 밖 잡선은 회색(205)으로 칠한다. 크기 변경, 캔버스 변경, PNG 저장은 하면 안 된다. 좌표가 틀어진다.
- **치수 검수(Map QC)**: `map_measure.py`로 내 지도와 기준 맵의 벽 범위, 창고 안쪽 가로, 협로 폭을 비교한다. 기준 맵 대비 1.5% 이내 또는 1픽셀(0.05m) 이내면 합격이다. 눈대중이 아니라 숫자로 판정해야 나중에 주행 문제가 지도 탓인지 설정 탓인지 가릴 수 있다.
- **정렬 확인**: 지도 서버 + `map→odom` 고정 변환(`--x -5.0 --y -3.5`) + RViz로 LiDAR 점이 지도 벽 위에 겹치는지 본다. 지도 서버는 Nav2 lifecycle 노드라서 `lifecycle_bringup`으로 활성화해야 `/map`을 발행한다.

**실행한 것**
```bash
python3 scripts/make_world.py worlds/walls.csv worlds/project_world.sdf
lift_build && ros2 launch amr_basics project_world.launch.py
ros2 run tf2_tools view_frames                                    # TF 트리 PDF
ros2 run amr_basics where_am_i --ros-args -p use_sim_time:=true
ros2 launch slam_toolbox online_async_launch.py use_sim_time:=true
ros2 run nav2_map_server map_saver_cli -f floor1_raw --ros-args -p use_sim_time:=true
python3 scripts/align_map.py maps/floor1_raw.yaml --dx -5.0 --dy -3.5
python3 scripts/make_map.py worlds/walls.csv maps/ref/
gimp floor1.pgm
python3 scripts/map_measure.py maps/floor1.yaml --ref maps/ref/floor1.yaml
ros2 run nav2_map_server map_server --ros-args -p yaml_filename:=$HOME/project_lift/maps/floor1.yaml -p use_sim_time:=true
ros2 run nav2_util lifecycle_bringup map_server
ros2 run tf2_ros static_transform_publisher --x -5.0 --y -3.5 --frame-id map --child-frame-id odom
```

**내가 만든 것**
- `worlds/project_world.sdf`, `launch/project_world.launch.py`
- `amr_basics/where_am_i.py` (`setup.py`에 실행 이름 추가)
- `params/slam.rviz`
- `maps/floor1_raw.*`(SLAM 원본), `maps/floor1.*`(후처리한 운영 맵), `maps/floor1_graph.*`(포즈 그래프), `maps/ref/`(기준 맵), `maps/floor2.*`
- `scripts/align_map.py`, `docs/map_qc.md`(검수표)
- `media/M2_map_before_after.png`, `media/M2_align.png`
- `6일차: 프로젝트 월드, floor1 운영 맵, 맵 검수 (M2)`로 커밋하고 `M2` 태그

**결과**
- Gazebo에 벽, 랙 3열, 색깔별 바닥 표식, 작업자 2명, S1 위의 TurtleBot4가 보였다.
- `where_am_i`는 odom 기준으로 스폰 자리를 (0, 0)으로 보여 줬다.
- 권장 경로대로 1층을 돌아 S1로 돌아온 뒤 완성 판정 4항목(외곽 폐합, 랙 3개, 엘리베이터 칸, 통로에 회색 없음)을 확인하고 저장했다. SLAM은 지도 서버를 켜기 전에 반드시 껐다.
- `align_map.py`로 origin을 월드 기준으로 옮겼다.
- 검수 결과를 `map_qc.md`에 옮겨 적고 판정했다. 랙 길이는 GIMP에서 픽셀 수를 세어 0.05를 곱했다.
- 정렬 확인 화면에서 LiDAR 점이 지도의 벽 위에 겹쳤다.

## 문제와 해결
| 문제 | 원인 | 해결 |
|---|---|---|
| 지식베이스만 붙인 챗봇이 주문번호 질문에 답하지 못함 | 챗봇은 문서만 알고 주문 데이터는 모른다. | Chatflow에서 질문 분류기로 주문 조회를 나누고, HTTP 요청으로 4일차 `/orders` API를 불렀다. |
| Dify Cloud에서 `localhost:8000`을 부를 수 없음 | Cloud 서버 입장에서 localhost는 자기 자신이다. | cloudflared 임시 터널 주소를 HTTP 요청 노드에 넣었다. 실습 후 터널을 껐다. |
| DSL 파일에 터널 주소가 남음 | HTTP 요청 노드의 URL이 그대로 내보내진다. | 저장 전에 `https://YOUR-API-URL`로 바꿨다. |
| RViz에 지도가 안 나올 수 있음 | 지도는 한 번만 발행되는데 RViz가 늦게 켜지면 놓친다. | Map 디스플레이의 Durability를 Transient Local로 바꿨다 (3일차 QoS). |
| SLAM 원본 지도에 점 노이즈와 작업자 자국이 남음 | 반사와 사람 모델도 LiDAR에 찍힌다. | 사본(`floor1`)을 만들어 GIMP에서 흰색·검정·회색으로 칠했다. 크기는 바꾸지 않았다. |
| SLAM과 지도 서버를 같이 켜면 위치를 잃음 | 두 노드가 모두 `/map`을 발행한다. | SLAM을 끈 뒤에 지도 서버를 켰다. |
